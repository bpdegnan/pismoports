# Top-level ports that pismoports exists to support.
# Add a port name here and run tools/update_pismoports_tree.py to pull it (and
# its full dependency closure) in from macports-ports.

git
subversion
TeXShop

# Editor. vim 9.1 has +job/+channel, so asynchronous linting (ALE driving
# chktex, gcc -fsyntax-only, ...) works without a language server -- which
# matters because no LSP server is realistically runnable on a G3.
vim

# Second editor, being attempted rather than assumed. The blocker was always
# LuaJIT, which neovim embeds as its scripting engine -- a JIT with a
# hand-written assembler backend per architecture, and upstream LuaJIT does not
# list Darwin/PowerPC among its supported targets. But MacPorts' luajit port
# sets no known_fail and no supported_archs, and carries a powerpc.patch, so
# it does not consider ppc broken. luajit's own dependencies are only gcc14,
# libgcc and legacy-support, all of which are built -- so this is one build to
# try, not a dependency excavation.
#
# If luajit will not go, neovim can be built against plain Lua 5.1 with
# -DPREFER_LUA=ON; that needs Portfile surgery (the port hardcodes
# luv-luajit) and gives up the JIT, but it is a supported upstream mode.
neovim

# pkill/pgrep, which Tiger does not ship. Installed on yebisu by hand; listed
# here so regenerating the tree does not prune it back out.
proctools

# The classic BSD game collection. Only needs ncurses and pkgconfig, both of
# which the tree already carries.
bsd-games

# Runs the latex -> bibtex -> latex -> latex cycle until the references stop
# moving. noarch, use_configure no, and its only runtime dep is texlive-latex,
# so it costs nothing and saves four slow passes by hand on a G3.
latexmk

# Spell-checking prose. Needed no new dependencies at all.
aspell
aspell-dict-en

# Long jobs on this machine are measured in hours over ssh, and a dropped
# connection currently kills them. Only new dependency is libevent.
tmux

# Plotting, mainly to get ngspice results into papers. Our copy of the Portfile
# differs from upstream in two ways, both recorded in the Portfile itself:
# gd2/webp/libcaca dropped (gd2 pulls libheif), and the Qt terminal removed
# from default_variants on darwin 8, where upstream's `os.major < 19` test
# would otherwise select Qt 4.
#
# NOTE ON DISTRIBUTION: gnuplot is license Restrictive, and MacPorts does not
# ship binaries for it for that reason. Keep its archive OUT of the public
# mirror at degnanresearch.com and seed it to yebisu directly instead.
gnuplot

# Tiger's own ssh is OpenSSH_5.1p1 with OpenSSL 0.9.7l, which cannot negotiate
# with GitHub or any current server, so git-over-ssh remotes fail. Needed no
# new dependencies.
openssh

# bsdowl was asked for alongside bsd-games and is PARKED, not rejected. It
# needs four ports this tree does not have:
#
#   bmake, ocaml, ocaml-findlib  -- plausible. MacPorts' ocaml is 4.14.1, which
#       lists ppc and ppc64 in supported_archs and ships
#       patch-configure-darwin-ppc.diff, so PowerPC is still handled there.
#   GraphicsMagick              -- the problem. Its depends_lib is unconditional
#       (not a variant) and pulls libheif, libjxl, libzip and netpbm.
#
# libjxl is where this would most likely die: a C++17 JPEG-XL codec depending on
# highway, a SIMD abstraction layer with little exercise on 32-bit PowerPC.
#
# If revisited, check FIRST whether bsdowl genuinely needs GraphicsMagick or
# only uses it for optional image conversion in its LaTeX rules -- patching that
# dependency out avoids libjxl and libheif entirely and makes the rest routine.

# GNU Forth, for practising against the Pismo's Open Firmware. Needed no new
# dependencies -- libtool and libffi were already here.
#
# Worth being clear about what this does and does not give you: gforth is ANS
# Forth. Open Firmware is IEEE 1275, which is ANS Forth plus a device-tree
# vocabulary (dev, .properties, select-dev, show-devs and friends) that gforth
# has no reason to implement. So this is the right tool for learning the
# language and trying out word definitions, and the real OF prompt on the
# machine (Cmd-Opt-O-F at boot) is where the 1275-specific parts get practised.
gforth

# Tiger ships zsh 4.2 from 2004. This is 5.9, for a usable interactive shell.
# Deps (gdbm, libiconv, ncurses, pcre) were all already in the tree.
#
# htop was asked for at the same time and is deliberately NOT here. Its Darwin
# backend is built on libproc -- darwin/DarwinProcess.c and
# darwin/DarwinProcessTable.c both #include <libproc.h> and call proc_pidinfo()
# -- and that API arrives in 10.5. Tiger has neither /usr/include/libproc.h nor
# sys/proc_info.h, and legacysupport does not provide them. Supporting it means
# writing a new process-enumeration backend against sysctl(KERN_PROC), which is
# a port of htop rather than a patch to it.
zsh

# A terminal for when tmux needs more than Tiger's Terminal.app gives it:
# OSC 52 clipboard, mouse reporting and 256 colours, none of which
# Terminal.app had before 10.7. Runs under X11. The xterm Tiger ships in
# /usr/X11R6/bin is from 2005 and predates all three. New deps were only
# luit and xorg-libXinerama; the rest of its X stack was already here.
xterm

# JSON on the command line. gh cannot exist here -- Go has no 32-bit PowerPC
# target on any OS, and gccgo's libgo was never finished for Darwin -- so
# GitHub's REST API is reached with curl instead, and jq is what makes the
# replies usable from a shell script. Plain C; only new dep is oniguruma6.
jq

# Text web browser, built +ssl (the Portfile default) against MacPorts'
# OpenSSL 3 -- TLS 1.3 and current ciphers, where Tiger's own OpenSSL 0.9.7
# can no longer complete a handshake with most sites. Every dependency was
# already in the tree; only www/lynx itself is new.
lynx

# Circuit simulator, so paper work can be checked on the Pismo. These come
# from bpdegnan/macportseda, NOT from macports-ports -- eda-ngspice47 installs
# into its own prefix (libexec/eda/ngspice47) and is reached via `port select`.
# It needs the eda-github PortGroup, also copied from that tree, which prints
# "report this to macportseda, not MacPorts trac" on a failed phase.
# Cheaper than the stock ngspice port because it does not depend on
# ngspice-docs, which is what drags in xmlto/w3m/libxslt.
eda-ngspice47
eda-ngspice_select

# A working LaTeX install roughly matching TeX Live's "basic" install
# scheme (plain TeX + core LaTeX + widely-used recommended packages +
# recommended fonts), without the huge lang-*/full collections.
texlive-basic
texlive-latex
texlive-latex-recommended
texlive-fonts-recommended

# IEEEtran, for submitting to IEEE. The class file alone is not enough -- the
# bibliography style is what makes an IEEE paper come out right -- and
# texlive-publishers carries the whole set:
#
#   tex/latex/ieeetran/IEEEtran.cls
#   bibtex/bst/ieeetran/IEEEtran.bst        (+ N, S, SN, SA variants)
#   bibtex/bib/ieeetran/IEEEabrv.bib, IEEEfull.bib, IEEEexample.bib
#
# texlive-latex-extra is a hard dependency of it, not a separate want. Both are
# texmfport (noarch) packages -- no compiling, just repacked trees -- so they
# cost build time only in unpacking, and install below texmf-texlive where
# kpathsea finds them with no per-user setup.
texlive-latex-extra
texlive-publishers

# Scientific Python on 3.11: arrays, 2-D geometry and plotting. All three
# resolve to py311-* through the python PortGroup default pinned to 311.
#
# numpy is built WITHOUT an external BLAS -- see the noblas variant in
# python/py-numpy. Upstream defaults to OpenBLAS on anything older than macOS
# 13.3, and OpenBLAS carries hand-tuned AltiVec kernels for PowerPC: G4 code,
# which a G3 cannot execute. numpy falls back to its bundled lapack_lite,
# f2c-translated plain C. Slower linear algebra, nothing that can fault.
#
# matplotlib pulls tk/tkinter in by default; the Agg backend (render to a
# file) needs no X server, the Tk window does.
py311-numpy
py311-shapely
py311-matplotlib

# Graph algorithms (shortest paths, components, flows). Pure Python and
# noarch, with no runtime dependencies beyond python311, so there is nothing
# in it that could carry G4 code.
py311-networkx

# Data frames and the rest of the scientific stack. scipy needs a real
# BLAS/LAPACK (numpy's bundled lapack_lite is not exported to other packages),
# and upstream again defaults to OpenBLAS; python/py-scipy here adds +netlib,
# netlib's reference BLAS/LAPACK from math/lapack -- plain Fortran, no AltiVec.
py311-pandas
py311-scipy
# Statistical plotting on top of matplotlib and pandas; pure Python.
py311-seaborn

# HDF5 from Python. h5py is HDF5 as numpy arrays; PyTables is what pandas'
# read_hdf/to_hdf use. Checked for G4 code: c-blosc2 has AltiVec shuffle
# routines but its CMakeLists only enables them for ppc64le, so 32-bit
# PowerPC gets the generic code (worth re-checking on upgrade -- if enabled,
# its cpu-feature probe reports AltiVec unconditionally, with no runtime
# test). c-blosc 1.x has no AltiVec; hdf5, numexpr, lzo2, snappy are plain.
py311-tables
py311-h5py

# Icarus Verilog. Costs NOTHING new on its own -- all seven of its deps
# (bzip2, readline, zlib, bison, autoconf, gperf, legacy-support) were already
# here, so the closure did not grow by a single portdir.
#
# It also arrives better prepared for this platform than most: the Portfile
# already carries legacysupport with newest_darwin_requires_legacy 10 (for
# strndup, the only old-API call in the whole source), a patch for
# _NSGetExecutablePath, and compiler.cxx_standard 2011. The source asks for
# -std=c++11 but uses none of <thread>, <mutex>, <atomic>, <chrono>,
# <unordered_map> or <regex>, so it avoids the C++11 runtime corners that
# break on a 2005 OS.
#
# The one thing that should have been fatal -- `-Wl,-rpath,${prefix}/lib`,
# when @rpath did not exist until 10.5 -- is already handled by devel/ld64,
# which builds +tigerrpath by default on darwin 8 and is patched both to stop
# erroring on -rpath and to stop emitting the atom. Nothing needs the rpath
# anyway: libvvp.so gets an absolute -install_name instead.
iverilog

# The HTML documentation, rebuilt against Python 3.11 rather than upstream's
# 3.12 -- see the subport in science/iverilog/Portfile for why.
#
# This is the expensive half: 33 new portdirs, all of them pure-Python
# (py-sphinx and its tree, plus docutils/hatchling/pygments/sphinx _select
# stubs). They are noarch, so they repack rather than compile and carry no
# Tiger risk -- but it is 33 ports of churn for documentation. Drop this root
# if the tree should stay lean; iverilog itself does not depend on it.
iverilog-docs

# BearSSL: a small, self-contained TLS library in portable C (no assembly
# required), useful where OpenSSL is too heavy. Upstream's port already sets
# -DBR_LOMUL on 32-bit PowerPC (slow multiplier). BearSSL's POWER8 AES/GHASH
# code is only enabled when the compiler targets POWER8 with crypto
# extensions, which a G3 build never does.
bearssl

# General-purpose Python 3.11 libraries. Almost all pure Python; the only
# compiled pieces are libyaml (plain C, for py-yaml) and greenlet (a small C
# extension py-sqlalchemy uses). Deliberately NOT here, because they need
# Rust, which has no PowerPC Darwin target: cryptography (and so paramiko),
# pydantic v2, orjson, polars, modern jsonschema (rpds-py) -- and with it
# Jupyter. psutil needs libproc, which Tiger lacks (same wall as htop).
py311-sympy
py311-yaml
py311-click
py311-rich
py311-tqdm
py311-tabulate
py311-beautifulsoup4
py311-openpyxl
py311-pybtex
py311-serial
py311-sqlalchemy

# The interactive shell. About twenty small pure-Python dependencies
# (prompt_toolkit, jedi, parso, traitlets...), no compiled code.
py311-ipython
